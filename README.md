# AVF Repair v2

Статический многостраничный сайт AVF Group. HTML, CSS, JavaScript без клиентских библиотек. Изменения по ТЗ выполнены в feature/engineering-repair-spec. Merge в main и production-публикация требуют отдельного подтверждения.

## Запуск

Требуется Node.js 22 или новее, npm-зависимостей нет.

```sh
node scripts/build.mjs
node scripts/og.mjs
node scripts/check.mjs
node scripts/serve.mjs
```

Открыть http://127.0.0.1:4174/avf-repair-v2/ . Сервер специально использует поддиректорию, как GitHub Pages.
`docs/` можно раздавать любым статическим сервером.

## Где редактировать

- src/data.mjs — 7 услуг, 6 проектов, FAQ, этапы, регионы, подтверждённые показатели.
- src/config.mjs — основной URL, контакты, аналитика, параметры формы.
- scripts/build.mjs — переиспользуемые шапка, подвал, формы, карточки, фильтры, сравнение, breadcrumbs, страницы и JSON-LD.
- src/app.js — интерфейс, валидация, локальные фото, события и UTM.
- src/style.css — адаптивная сетка и общий визуальный стиль.
- src/architecture.svg — схема первого экрана.
- scripts/og.mjs — лёгкая PNG-обложка для Open Graph.
- docs/ — результат сборки. Не менять вручную: следующая сборка перезапишет HTML, CSS и JS.

CMS можно подключить как источник данных для статической сборки, сохранив интерфейсы массивов services/projects/faq.

## Форма и аналитика

По умолчанию endpoint пуст: сеть не используется, состояние demo-ready означает только успешную локальную проверку. form_success в деморежиме не генерируется. Файлы не попадают в sessionStorage; object URL освобождаются после удаления/закрытия страницы. При выключенном JS кнопка отправки отключена.

Реальный endpoint должен принимать multipart/form-data: problem, name, phone, channel, consent и повторяющееся photos. Успех — HTTP 2xx и JSON {"success":true}; остальные ответы и таймаут 20 секунд показывают ошибку, сохраняя форму. Клиент не заменяет серверную проверку и защиту от спама. До активации endpoint необходимо утвердить правовые документы и обновить демонстрационные подписи в шаблоне формы и privacy.html.

Настройка счётчиков — analytics.ga4 и analytics.metrika. Пустые значения не загружают сторонние скрипты. Отключены автоматические просмотры GA4 и автоматические сборщики Метрики; подготовлены ручные события. События доступны в dataLayer, в настроенные счётчики уходят только имена событий и разрешённые метаданные (тип/slug страницы, количество файлов, режим, код причины). Никаких значений полей формы, имён файлов или фотографий.

События: click_phone, click_messenger, service_view, project_view, form_start, photo_upload, form_submit, form_success, form_error. События контактов становятся доступны после заполнения реальных ссылок в конфигурации. Сохраняются только 5 стандартных UTM-меток текущей сессии вкладки, они передаются во внутренних HTML-ссылках. Метки не включаются в пользовательские события.

## SEO и перенос

У каждой страницы уникальные title/description, H1, canonical, Open Graph; сгенерированы Organization, Service, BreadcrumbList, sitemap.xml, robots.txt. Измените baseUrl в src/config.mjs и пересоберите сайт для нового домена. Все пути ресурсов и ссылок относительные, работа из поддиректории поддерживается.

На GitHub Pages project site файл /avf-repair-v2/robots.txt не управляет обходом всего домена: робот читает /robots.txt в корне origin. При переносе разместить сгенерированный robots.txt в корне основного домена.

## Публикация — только после подтверждения

1. Проверить CONTENT_TODO.md и QA_REPORT.md.
2. Выполнить сборку, генерацию OG и проверки командами выше.
3. После отдельного подтверждения принять ветку в main и отправить main в GitHub.
4. GitHub Pages публикует /docs ветки main. Дождаться built для актуального коммита и проверить URL.

До подтверждения допустимы локальный просмотр и ревью ветки. Публичная версия v2 остаётся прежней.
